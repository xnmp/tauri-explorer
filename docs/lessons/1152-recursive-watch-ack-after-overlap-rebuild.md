# 1152: a recursive-watch write can go unacknowledged when it lands during an overlap rebuild

- Under 24 CPU hogs, `issue_651_real_streaming_command_reuses_refreshes_and_cancels_listings` failed about 1 run in 30 to 45 with "specific filesystem write was not acknowledged by recursive observation". It was not a lost inotify notification and not an overflow. The raw-event log (the existing `tauri_explorer_lib::native_watch_diagnostics` debug target) showed the kernel delivering `Remove`/`Create` for the write, with no `rescan=true` event.
- The write that failed was the third receipt, right after the test released the overlapping parent watch. Releasing an overlapping recursive root queues a rebuild of every surviving root on the search worker (ADR 0013). Until the worker reaches that command, the published coverage still reports the old generation as healthy, so `ensure_search_cache_watched` returns `true` at once. The write then reached only the generation being retired (state `ACTIVE|FAULTED`), which correctly refuses per-path delivery. The new generation registered about 4 ms later. The product is unaffected: the fault (`Lost`) and the rebuild (`Invalidated`) both advance the root's cache epoch, so a listing taken before or during the gap cannot be reused. Only the test's per-path receipt, which needs a live-generation `Changed` notice, never arrived.
- Before a real-watcher write that a receipt must acknowledge, call `arm_recursive_watch(root)` (backed by `fs_watcher::arm_search_watch_for_test`). It drains the recursive worker's queue (`SearchObservation::settled`, waited on after releasing the watcher lock) and then arms and confirms coverage. Arm **before** taking the cache revision the write must advance, because arming after a release can itself advance the epoch and stand in for the write.
- To log raw native events in a test run, install any `log::Log` implementation and set the max level to `Debug`; the `native_watch_diagnostics` lines include each event, its `rescan` flag (notify maps `IN_Q_OVERFLOW` to `Flag::Rescan`), and the fault/defer/deliver classification.
