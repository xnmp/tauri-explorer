# Arch installer skipped dependency preparation

The local installer passed `makepkg -e` (`--noextract`). This skips both source extraction and `PKGBUILD.prepare()`, despite combining it with `--cleanbuild`. Preparation is where the package installs JavaScript dependencies with `bun install --frozen-lockfile`. After pulling a version that added PDF preview, an existing checkout without `pdfjs-dist` reached the build and failed copying `node_modules/pdfjs-dist/cmaps`.

Remove `-e` so package preparation runs before each build, and set `BUILDDIR` to an ignored `.arch-build/` directory. Without an explicit build directory, makepkg stages directly in the checkout's `src/`, which is also the frontend source directory: enabling `--cleanbuild` there could delete the application source. The local `_srcdir` continues to point at the checkout, while staging is isolated. Keep the dependency install in `prepare()` rather than adding a second install path to the wrapper.

An isolated fixture ran the actual installer and system `makepkg`, with a controlled dependency installer and intercepted privileged installation request. The original failed with the reported PDF asset ENOENT and never ran preparation; the fixed script prepared dependencies, copied all four asset directories, created its package and reached the installation request while preserving a source sentinel in the checkout's `src/`. A repeated clean build also preserved the sentinel and removed only stale staging sources. Restoring only `-e` reproduced the failure. This exercises preparation/packaging order, not a full native app build. The affected checkout's actual frozen install and PDF asset preparation also passed.
