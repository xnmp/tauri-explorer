# #1269: spring-load follow-ups

- **A caller that outlives its drag must name the drag.** A replayed drop (`handleDomDrop` after a pending native start) and the lost-Leave fallback both end springs later. The controller (`domain/spring-load.ts`) now keeps the gesture of the last hover (the in-app source's `sessionId`), and `end(scope)` / holds only act on that gesture. A hover from a different session is a new drag: it ends the older one and releases its holds.
- **Never derive the gesture from something that can vanish mid-drag.** A first attempt fell back to an "external" id when `dragState.latestSource()` was null; a virtualised source row unmounting under a big peek flipped the gesture and closed the peek under the pointer (caught by the "source row leaves the virtual window" E2E). No session means "leave the gesture alone".
- **Lost native Leave (Linux).** The DOM dragend skips `springEnd` while the native receiver reports, expecting a native Drop/Leave. `springEndSoon` arms a 500ms fallback (injectable `lostLeaveMs`/timer); native Enter/Leave/Drop, a DOM dragstart or any `end` cancel it, and it only ends the gesture it was armed for.
- **`.content.drop-target`** is the listing background's own highlight. A folder drop stops at its row, so the background never saw a drop or leave. It now goes through `useBackgroundDropFeedback`, gated on the `retireDropFeedback()` epoch like every folder highlight.
- **Native probe.** `springPeekOpenedAfterEnd` records whether the drag (dragend or receiver Drop) had already finished when the peek appeared; the Details selector also matches the rows of a populated destination (`.entry-item[data-path^="<folder>/"]`), not only the empty-folder state row.
- **Never resolve a drop against layout that may have changed after the gesture ended.** The lost-Leave fallback closes temporary peeks 500ms after dragend; a native Drop reaching JS later (main-thread stall, slow Wayland transfer) then hit-tested a shifted layout and moved files into the wrong folder. At dragend the handler now captures the target under the last native Over (`endedDrag`); the fallback reports its expiry (`springEndSoon(expired)`), and a Drop after expiry routes to the captured target, or cancels with a toast if none. A Drop before expiry still resolves from its own position.
- **Replays are scoped too.** The replayed DOM drop re-enters `handleDomDrop`; it now carries the gesture it was dropped in (`replayGestures`) and only ends springs/feedback if that drag is still the live one. A pending drop's hold also defers the fallback (`keepOpen`/`endDeferred`) so its replay still finds its row.
- **Native e2e must not be masked by the backstop.** `assertSpringClosed` measures the peek's closure against the last end signal (dragend or receiver Drop) and requires it well under the 500ms fallback.
