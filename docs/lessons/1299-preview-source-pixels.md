# Preview pixel metadata must describe the source (#1299)

The Preview image surface can show a display rendition of a large image. Its `naturalWidth` and `naturalHeight` describe that rendition (1024 × 577 in the report), not the file. Measuring the displayed element therefore produced plausible but incorrect pixel metadata.

Rendition loads now obtain source dimensions through the existing bounded `get_image_resolution` header reader while decoding the rendition. Source dimensions travel with the versioned image cache/content replacement; originals use their decoded intrinsic dimensions. A held image has no metadata for the new selection. Pending image and audio-cover selections reserve the Pixels row with an em dash, so suppressing stale dimensions does not reflow the held image in right or vertical docks. Successful previews keep that placeholder when source dimensions are unavailable; removing the row at completion would shift the image again. Errors and previews without an image surface have no pixel row. Stale request owners cannot publish metadata after selection or file-revision changes.

The regression browser test deliberately decodes 1024 × 577 while reporting a 7680 × 4320 source. Unit contracts cover unavailable headers, malformed dimensions, superseded loads, same-path edits and cached revisits. The existing Rust header-reader tests exercise actual temporary image files independently of the browser mock.

The selection-stability browser test samples every animation frame across a delayed image replacement in both right and bottom docks. A separate slow-load contract observes the initial placeholder and a held image with different replacement dimensions, then verifies the selected image's dimensions replace the placeholder. Both docks also cover a successful rendition with an unavailable source header, asserting that every sampled image box stays stable and the final Pixels value remains unknown. Error and image-to-text transitions remove the pixel row.
